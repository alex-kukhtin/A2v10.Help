Прості моделі даних

Моделі даних

Найпростіша модель - це один об'єкт зі скалярними властивостями. Такій моделі відповідає один набір даних типу Object, який повертає рівно один рядок.

Завантаження моделі

Ця процедура має назву моделі із суфіксом .Load або .Index. Зверніть увагу, що оновлення індексних моделей не підтримується!

Ім'я першого поля описує сам набір: Agent - ім'я властивості в корені моделі, TAgent - ім'я типу, Object - тип набору. Значення цього поля завжди null. Детальніше про побудову імен - Загальна інформація.

Спеціальні поля

Поля без модифікатора стають звичайними властивостями моделі. Два модифікатори мають особливе значення:

Модифікатор Опис
!Id Ідентифікатор запису. За ним виконується зв'язування з іншими наборами - зокрема з наборами типу Map.
!Name Найменування. Використовується там, де об'єкт потрібно показати одним рядком - наприклад, у полі вибору посилання.

Обидва модифікатори записуються без імені типу, тому в імені поля стоять два знаки оклику підряд: [Id!!Id], [Name!!Name]. Ім'я властивості при цьому довільне - модель отримає саме його.

Посилання

Поле з модифікатором !RefId містить посилання на інший об'єкт. В базі даних це звичайний зовнішній ключ, але в моделі така властивість стає об'єктом, а не числом.

Самі об'єкти повертаються окремим набором типу Map. Такий набір, як правило, не має імені - він не створює власної властивості в моделі, а лише постачає дані для посилань. У ньому обов'язкове поле з модифікатором !Id: саме за ним відбувається зв'язування.

Результат:

Зв'язування виконується за парою ім'я типу + значення ідентифікатора. Звідси три наслідки, про які варто пам'ятати:

  • Порядок наборів не має значення. Набір Map може бути повернутий як до, так і після набору, що містить посилання.
  • Тип значення повинен точно збігатися з типом поля !Id в наборі Map. Значення int 22 і bigint 22 - це різні ключі, і зв'язування не відбудеться.
  • Якщо запису в наборі Map немає, властивість залишиться порожнім об'єктом. Помилки не буде - форма просто покаже порожнє значення.

Один набір Map обслуговує всі посилання свого типу, скільки б їх не було в моделі. Про формування наборів Map для переліків див. Розбиття на сторінки.

Іменований Map

Якщо набору Map дати ім'я, він з'явиться в моделі - і при цьому продовжить обслуговувати посилання. Тобто ті самі дані одночасно і розв'язують посилання, і доступні як окрема властивість.

Це зручно для невеликих довідників, вибір з яких потрібно робити прямо на клієнті, не звертаючись до сервера: перелік уже є в моделі, і його можна відразу прив'язати до елемента вибору.

В моделі така властивість буде масивом елементів.

Набір Map завжди повинен містити поле з модифікатором !Id - саме за ним відбувається зв'язування.

Новий екземпляр

Якщо запису з переданим ідентифікатором не існує, набір даних не поверне жодного рядка. Однак метадані будуються за іменами полів, а не за їх значеннями - тому вони будуть побудовані й для порожнього набору.

Платформа конструює об'єкт за метаданими, і форма отримує повноцінний екземпляр моделі правильної структури - з усіма властивостями потрібних типів і порожніми значеннями. Саме так завантажується форма створення нового запису: окрема процедура для цього не потрібна, працює та сама .Load.

Щоб задати початкові значення нового екземпляра, використовують системний набір $Defaults. Детальніше...

Збереження моделі

Збереження моделі виконується в два етапи. На першому викликається спеціальна процедура, яка повертає метадані - правила, яким чином перетворити ієрархічну модель json на таблиці. На другому етапі викликається процедура збереження, яка і зберігає модель.
