Системні набори даних

Моделі даних

Окрім наборів даних, які формують саму модель, збережена процедура може повертати системні набори. Вони не створюють властивостей моделі безпосередньо, а керують тим, як платформа обробляє інші набори: задають параметри розбиття на сторінки, фільтри, значення за замовчуванням тощо.

Системний набір розпізнається за іменем типу в першому полі набору. Імена всіх системних типів починаються з символа $. Як і для звичайних наборів, значення першого поля завжди має бути null.

Тип Опис
$System Параметри розбиття на сторінки, сортування, фільтри та ознаки моделі.
$Aliases Підстановка імен полів, які обчислюються під час виконання процедури.
$Defaults Тільки NET.Core Значення за замовчуванням для нового (незавантаженого) екземпляра моделі.

$System

Найчастіше вживаний системний набір. Його основне призначення - повернути у форму той стан, з яким вона була завантажена: поточну сторінку, порядок сортування та значення фільтрів. Без цього набору форма втратить ці значення при кожному оновленні даних.

Набір складається з одного рядка. Перше поле - [!$System!] зі значенням null, всі інші поля описують окремі параметри.

Зверніть увагу: значеннями є параметри процедури, а не константи. Саме тому цей набір повертає у форму те, з чим її було викликано.

Модифікатори набору $System

Другий елемент імені поля вказує, до якого елемента моделі відноситься параметр (в прикладі вище - до масиву Documents). Третій елемент - сам модифікатор.

Модифікатор Ім'я елемента Тип значення Опис
PageSize обов'язкове int Кількість елементів на сторінці.
Offset обов'язкове int Зміщення відносно початку (номер першого елемента сторінки).
SortOrder обов'язкове string Ім'я властивості, за якою відсортовано набір.
SortDir обов'язкове string Напрямок сортування (asc або desc).
GroupBy обов'язкове string Властивість, за якою виконується групування.
HasRows обов'язкове int або bit Ознака наявності рядків. Використовується для "лінивих" колекцій, вміст яких ще не завантажено: кількість елементів невідома, але відомо, що вони є.
Filter обов'язкове будь-який Значення фільтра. Ім'я елемента - складене. Див. нижче.
ReadOnly не вказується bit Якщо 1, платформа блокує всі елементи керування форми та забороняє збереження моделі.
Copy не вказується bit Ознака того, що модель завантажено в режимі копіювання.
Permissions обов'язкове int Бітова маска прав доступу до елемента.

Якщо для модифікаторів PageSize, Offset, SortOrder, SortDir, GroupBy, HasRows, Filter або Permissions не вказано ім'я елемента, виникає помилка завантаження моделі.

Поле з невідомим модифікатором не є помилкою - його значення додається до системних властивостей моделі "як є", під власним ім'ям.

Форма запису Опис
Documents.Fragment Простий фільтр. Значення будь-якого скалярного типу.
Documents.Period.From

Documents.Agents.TAgent.Array Масив посилань. Значення - рядок з переліком ідентифікаторів через кому. Кожен з них має бути присутнім у наборі типу Map.

Значення фільтра має бути прочитане формою під тим самим іменем. Про використання фільтрів у поданнях див. Розбиття на сторінки.

$Aliases

Структура моделі описується іменами полів, а ім'я поля в SQL - це літерал. Обчислити його під час виконання неможливо, не вдаючись до динамічного SQL. Набір $Aliases знімає це обмеження: справжнє ім'я поля передається як значення, а значення SQL обчислює як завгодно.

Кожне поле набору - це псевдонім, а його значення - повне ім'я, яке цей псевдонім замінює. В наступних наборах замість повного імені пишеться псевдонім.

Набір $Aliases має бути повернутий перед першим використанням псевдонімів. Псевдоніми застосовуються тільки до наборів, які йдуть після нього. Імена, для яких псевдонім не визначено, використовуються без змін.

Підстановка застосовується до всіх імен полів у наступних наборах. Тому псевдонім не повинен збігатися зі справжнім іменем якогось поля - інакше це поле буде мовчки замінено. Саме для цього псевдоніми починають з символа ~: таке ім'я свідомо не може зустрітися серед звичайних полів.

$Defaults

Тільки NET.Core Набір $Defaults задає значення за замовчуванням для властивостей моделі. Значення застосовуються тільки до тих елементів кореня моделі, які не були завантажені. Завдяки цьому набір можна повертати безумовно, не аналізуючи, створюється новий екземпляр чи завантажується існуючий.

Ім'я поля - це шлях до властивості моделі, елементи якого розділені крапкою. Проміжні об'єкти створюються автоматично.

  • Значення null ігнорується - задавати порожнє значення за замовчуванням не має сенсу.
  • Підтримується модифікатор RefId. Об'єкт, на який вказує значення, має бути присутнім у наборі типу Map, при цьому тип значення повинен точно збігатися з типом ідентифікатора в цьому наборі (int 22 не дорівнює bigint 22). Сам набір Map може бути повернутий пізніше.
  • Рядкові значення локалізуються.
  • Підтримується модифікатор Utc для перетворення дати в локальний час.

Порядок наборів

Набори даних обробляються послідовно, один за одним. З цього випливають вимоги до їх порядку:

  • $Aliases має бути повернутий перед першим набором, у якому вживаються визначені в ньому псевдоніми.
  • $System має бути повернутий після того, як оброблено всі елементи моделі, на які він посилається. На практиці його зазвичай розміщують останнім.
  • $Defaults може бути розміщений у будь-якому місці - посилання (RefId) в ньому розв'язуються після обробки всіх наборів.
