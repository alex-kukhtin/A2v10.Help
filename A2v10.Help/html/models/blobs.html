Файли та зображення

Моделі даних

Тільки NET.Core Платформа сама зберігає файли, перевіряє їх і видає на клієнт. Прикладна програма бачить файл тільки як посилання: Id і токен доступу. Байтів файлу немає ні в таблицях програми, ні в її процедурах, ні в моделі.

Є два сценарії:

  • Файл у полі запису — один файл на запис: логотип контрагента, фото товару. Посилання зберігається в колонці таблиці.
  • Вкладення — скільки завгодно файлів у будь-якого запису. Посилання зберігаються в платформній таблиці зв'язків a2blob.BlobLinks.

Перевірка при збереженні

Перед Update платформа перевіряє кожне непусте посилання з розділу blobs: воно повинне прийти разом зі своїм токеном. Чесне посилання завжди має токен — з Load або з результату завантаження. Тому записати в поле чужий Id зі скрипту не вийде:

Увага! Перевіряються тільки поля кореневого об'єкта моделі (Agent.Logo). Файл у рядку документа (Document.Rows[].Photo) або у вкладеному об'єкті (Agent.Contact.Photo) не підтримується.

Вкладення

Одна кінцева точка обслуговує вкладення всієї програми. Власник вкладень визначається двома значеннями: base — адреса кінцевої точки власника, і Id запису. Приклад: кінцева точка /attachment.

model.json

requireBase означає, що кожен виклик цієї кінцевої точки повинен містити base. Платформа перевіряє ролі model.json, що лежить за адресою base, і тільки потім викликає процедуру. Ключ Upload тут не поле моделі, а просто ім'я, за яким завантажуються файли.

Відкриття з форми власника

Argument дає Id власника, SaveRequired зберігає новий запис, щоб цей Id з'явився.

Вид

Список файлів і перегляд вибраного. Вибраний рядок — через Slot: без виділення BlobPreview не відображається, а Fallback пояснює, чому місце пусте.

Власні колонки

Якщо вкладенню потрібен коментар або категорія, програма додає колонку сама, у своєму скрипті схеми: alter table a2blob.BlobLinks add Memo nvarchar(255) null (з перевіркою, що колонки ще немає) і пише її окремим викликом.

Обмеження

  • Явного видалення файлу немає. Замінений логотип, файл без збереження, видалений зв'язок залишаються в сховищі.
  • Файл незмінний: заміна — це завжди новий Id.
  • Зображення з файлу поки не друкується у звітах.
